# Рабочая область визуальной обратной связи для Astra

Здесь человек и Astra могут обсуждать одну и ту же фотографию и текущую 3D-сцену. Отметьте точку, обведите область, проведите линию или стрелку на фотографии либо в 3D-виде и добавьте короткий комментарий. Инструмент MCP передаст модели исходные изображения, изображения с пометками, снимки сцены и необходимый контекст. **Astra сама решает, что изменить: объект, камеру, материал или способ реконструкции.** Пользователю не нужно вводить координаты или геометрические ограничения.

![Фотография и сцена рядом с нанесёнными пометками](preview.png)

## Возможности

- Слева просматривайте фотографию, справа вращайте и масштабируйте текущую 3D-сцену и выбирайте объекты. Можно переключаться между несколькими фотографиями.
- На любой стороне можно поставить точку, нарисовать прямоугольник, линию, стрелку или текстовую пометку. При необходимости дайте пометкам с двух сторон одинаковый номер. Если объекта ещё нет в сцене, достаточно отметить его только на фотографии.
- Текущую фотографию можно полупрозрачно наложить на 3D-вид для визуального сравнения. **Автоматического совмещения камер нет**.
- После нажатия «Отправить Astra» тот же сеанс остаётся открытым. Когда Astra обновит сцену, страница обновится автоматически. Черновик пометок и ракурс сохраняются в браузере для следующего раунда.

Отправляемый пакет обратной связи содержит исходную фотографию, фотографию с пометками, исходный снимок текущей сцены и снимок с пометками, необходимые увеличенные фрагменты, комментарий, ID выбранных объектов, версию сцены и положение камеры просмотра. При выборе детали внутри GLB также передаются имя и путь выбранного узла. Изображения возвращаются как MCP image content; метаданные также доступны в structured content и тексте. На случай, если хост не пересылает блоки изображений MCP, указываются абсолютные локальные пути к файлам.

## Локальный запуск

Потребуются Python 3.11+ и браузер с поддержкой WebGL. В корне клонированного репозитория выполните:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python backend/server.py
```

Откройте <http://127.0.0.1:18765/> и загрузите фотографию. Справа по умолчанию показан пример — стул; после подключения вашей сцены появится ваш результат. Это отдельная рабочая область в браузере, поэтому клиенту не нужна поддержка встроенных MCP Apps. Сервер принимает соединения только на `127.0.0.1`. Импортированные изображения, сцены и обратная связь хранятся в `backend/data/`; эта папка исключена из Git.

## Подключение к Codex / Astra

Зарегистрируйте MCP-сервер из корня репозитория. `$PWD` развернётся в абсолютный путь к репозиторию:

```bash
codex mcp add scene_feedback -- "$PWD/.venv/bin/python" "$PWD/backend/mcp_server.py"
```

Установите в `~/.codex/config.toml` достаточно большое время ожидания взаимодействия для `[mcp_servers.scene_feedback]`. Измените секцию, уже созданную командой `codex mcp add`, не добавляя вторую секцию с тем же именем. Если вы используете режим Codex, который не запрашивает подтверждения, можно разрешить автоматическое выполнение только для инструмента создания рабочей области; инструменты чтения обратной связи объявлены доступными лишь для чтения. Затем перезагрузите конфигурацию MCP: [инструкция по настройке Codex MCP](https://learn.chatgpt.com/docs/extend/mcp).

```toml
[mcp_servers.scene_feedback]
tool_timeout_sec = 900

[mcp_servers.scene_feedback.tools.request_visual_feedback]
approval_mode = "approve"
```

Рекомендуемый порядок из двух вызовов:

```text
request_visual_feedback(
  reference_images=["/absolute/path/reference.jpg"],
  scene_glb_path="/absolute/path/current.glb",
  wait_for_submit=false
)
→ session_id, url, next_cursor

Пользователь делает пометки по адресу url и нажимает «Отправить Astra»

wait_visual_feedback(session_id, cursor=next_cursor)
→ блоки изображений + пометки/текст/объекты/камера/версия + новый next_cursor
```

Можно передать список объектов существующей сцены через `current_scene={"objects": [...]}` либо не передавать сцену и использовать ту, что уже открыта в рабочей области. `scene_glb_path` импортирует GLB для предварительного просмотра и не определяет способ моделирования Astra. Пути к GLB и фотографиям должны быть локальными путями на компьютере, где работает MCP-сервер. Фотографии также можно добавить прямо в браузере.

Получив обратную связь, Astra изменяет сцену собственными инструментами моделирования. Для следующего раунда вызовите `request_visual_feedback(session_id=..., scene_glb_path="/absolute/path/updated.glb", wait_for_submit=false)`, а затем `wait_visual_feedback` с возвращённым `next_cursor`. При повторном использовании того же `session_id` не нужно заново открывать страницу и загружать фотографии. Отправка с веб-страницы сама по себе не возобновляет уже завершённый ход Codex. Чтобы Astra продолжила работу, необходим ожидающий вызов MCP либо пользовательский хост, который запустит следующий ход.

Если хост умеет открывать локальный браузер, `request_visual_feedback()` по умолчанию пытается открыть страницу и дождаться отправки. Если страница не открылась, инструмент сразу возвращает URL; затем можно ждать через `wait_visual_feedback`. После истечения времени ожидания сеанс остаётся открытым: используйте `get_visual_feedback(session_id, cursor)` или начните ожидание снова.

## Формат обратной связи

Координаты пометок нормализованы относительно соответствующей фотографии или вида (`0–1`). Они обозначают место на экране, на которое указал пользователь. Это не мировые координаты и не команды моделирования. Например:

```json
{
  "scene_revision": 12,
  "note": "Верх шкафа должен быть примерно на уровне линии ① на фотографии слева; справа ещё не хватает светильника.",
  "selected_object_ids": ["cabinet"],
  "annotations": [
    {
      "pane": "reference",
      "reference_image_id": "<reference-id>",
      "type": "line",
      "group_id": "1",
      "coordinates": {"x": 0.23, "y": 0.32, "x2": 0.68, "y2": 0.32}
    },
    {
      "pane": "scene",
      "type": "point",
      "group_id": "1",
      "object_id": "cabinet",
      "coordinates": {"x": 0.54, "y": 0.46}
    }
  ]
}
```

`group_id` и `object_id` необязательны. При выборе узла внутри GLB обратная связь также содержит `selected_scene_nodes`: для каждого узла указываются ID объекта модели, путь из индексов дочерних узлов внутри GLB и доступное имя узла. Это вспомогательная ссылка на место в изображении, а не действие, которое модель должна выполнить. Исходная фотография и фотография с пометками хранятся отдельно, чтобы Astra могла отличить содержание снимка от подсказок человека. Если версия сцены изменилась, интерфейс показывает версию, к которой относятся старые пометки сцены; при отправке проверяется текущая версия, чтобы не принять старый кадр за новый. Сохранённые пометки отправляются и в следующем раунде; их можно удалять по одной или очистить все сразу.

Существующие инструменты `get_scene`, `update_scene`, `replace_scene` и `import_scene_model` по-прежнему доступны для отображения сцены и совместимости с прежними клиентами. Сама рабочая область не изменяет сетку GLB.

## Проверка и область применения

```bash
.venv/bin/python -m unittest discover -s backend/tests -v
```

Это прототип для доверенной локальной среды. Другие процессы на том же компьютере могут обращаться к странице и API сеансов; не открывайте локальный порт для недоверенных пользователей. Настройку автоматического разрешения применяйте только к доверенному локальному серверу. Проверено, что Codex CLI может прочитать содержимое фотографии из блоков изображений MCP этого инструмента. Передача изображений другими хостами зависит от их реализации. Если хост показывает только текст, Astra может прочитать файлы по локальным путям, указанным в обратной связи.
